## 4. Payment & banking security

**Microsoft's agent-framework package on PyPI hijacked to steal Azure and CI credentials** (17 Nov) `Act now`

OX Security reports that versions 1.26.1 and 1.26.2 of Microsoft's Python Agent Framework on PyPI carry a credential stealer. A .pth file runs it whenever Python starts, with no import needed, and it collects environment secrets, cloud and package-manager credentials, and Azure managed-identity tokens, then sends them to a webhook. The package still depends on the genuine agent-framework-core 1.26.0, so nothing visibly breaks. Microsoft had published no advisory in the sources found. It follows a similar compromise of Microsoft's durabletask SDK in May. [OX Security research, 17 Nov 2026](https://www.ox.security/blog/breaking-hijacked-releases-of-microsofts-official-agent-framework-steals-azure-and-ci-credentials/)

*Why it matters for us:* Our GenAI pilots, Databricks notebooks and AKS build images may pull this SDK. Check lockfiles and images for the two versions, or for site-packages/agent_framework_meta.pth. Rotate any secrets and managed-identity scopes those environments could reach. Enforce hash-pinned installs through our internal mirror with a quarantine delay for new releases.

**Coinbase blocks $4.7m in transfers to a deepfake giveaway scam** (18 Nov) `APP fraud`

Coinbase says its fraud systems stopped about $4.7m in customer transfers to a deepfake Elon Musk giveaway scam. Because victims sent the money voluntarily, authentication checks were no help, and detection depended on destination and behaviour signals. [BleepingComputer, 18 Nov 2026](https://www.bleepingcomputer.com/news/security/coinbase-blocks-47-million-in-transfers-to-elon-musk-deepfake-scam/)

*Why it matters for us:* Authorised push-payment fraud via deepfakes is the scenario PSR liability rules target. Our SEPA Inst and IRIS fraud scoring needs beneficiary-risk and behavioural signals in the sub-10-second window, not only SCA. This is worth sharing with the fraud team.

Agent Sandbox gives us a platform-native way to implement the containment standard discussed last issue. Confidential node pools and Chaos Studio GA are candidates for the AKS landing-zone baseline.

## 8. From InfoQ

**Architecture & Design: Governed autonomous intelligence for mission-critical systems** (16 Nov) `Reference design`

The article separates reasoning from execution. Agents correlate signals and propose actions but cannot touch production. A deterministic policy gate, driven by a versioned action catalogue, assigns each proposed action a risk class, and a single tool gateway enforces least privilege, argument validation and post-action health checks. Medium- and high-risk actions need human approval, autonomy is widened one action class at a time and can be revoked, and every action leaves a full audit chain. [InfoQ article, 16 Nov 2026](https://www.infoq.com/articles/utility-governed-autonomous-intelligence-ai/)

*Why it matters for us:* This is close to the pattern we need before any agent can act on IBM i, TIBCO or payment operations. The policy gate and gateway map onto APIM plus a rules service, and the audit record gives us DORA and AI Act evidence. It is a candidate SAB reference architecture.

**Architecture & Design: LinkedIn moves Spark shuffle to Apache Celeborn** (18 Nov) `Data platform`

LinkedIn runs more than 300,000 Spark jobs a day. It moved shuffle data off compute nodes onto dedicated Celeborn workers with a Raft-based control plane. Daily shuffle fetch failures fell from about 750 to 20, compute cost dropped 10% and runtimes improved 14%. [InfoQ, 18 Nov 2026](https://www.infoq.com/news/2026/11/linkedin-celeborn-remote-shuffle/)

*Why it matters for us:* Databricks manages shuffle for us, but the lesson carries over: separating state from elastic compute is what stabilises large batch estates. That matters for our end-of-day and regulatory-reporting pipelines.

**AI architecture: Uber's legal agent uses a rules engine that overrides the model** (16 Nov) `Pattern`

Uber's contract-redlining agent is a Word add-in on a LangGraph backend, with OpenSearch holding rules and past lawyer decisions. A deterministic rules engine overrides the model whenever a non-negotiable clause applies, and lawyers approve every suggestion. Uber reports 91% accuracy and contract reviews more than 20% faster. [InfoQ, 16 Nov 2026](https://www.infoq.com/news/2026/11/uber-legal-redlining-agent/)

*Why it matters for us:* Letting hard rules override model output, with feedback captured from experts, is a practical pattern for credit, KYC and complaints copilots, where policy must always win. It also gives model-risk reviewers a clear control point.

**AI architecture: Datadog adds A/B experiments for agents on live traffic** (17 Nov) `Evals`

Datadog's Online Experiments splits production traffic between agent variants using feature flags. It compares evaluator quality scores with latency, tokens, cost and errors, and keeps full tool-call traces. In one example, a cheaper model cut cost 44% at similar quality, but the traces showed it passed invalid tool parameters more often. [InfoQ, 17 Nov 2026](https://www.infoq.com/news/2026/11/datadog-ai-agent-observability/)

*Why it matters for us:* Controlled experiments on live traffic with traces are how a model or prompt change should go through change management under model-risk rules. Whatever observability stack we pick, we need this capability before scaling GenAI beyond pilots.

## 9. Top 3 from Medium

**Don't Trust the Ledger After a Crash: Payment Workflows in Go and Temporal — Victor Jonah (tag: payments)** (18 Nov)

The story shows how durable-execution replay, idempotency keys and compensation steps keep a payment consistent when a worker crashes mid-transfer and retries. Its core argument is that the workflow history, not the ledger state at crash time, is the source of truth for recovery. Summarised from the feed preview, as the story page could not be opened. [Medium — Victor Jonah](https://medium.com/@victorjonah/dont-trust-the-ledger-after-a-crash-payment-workflows-in-go-and-temporal-b4662cf6db5b)

*Why it matters for us:* It applies directly to SEPA Inst and IRIS orchestration across TIBCO and IBM i, where partial failures and duplicate postings are the main operational risk. It is a useful lens for reviewing our saga and idempotency standards.

**Kafka vs Message Queue: When to Use Which, Now That Kafka Has Queues — Santosh Yadav (tag: kafka)** (18 Nov)

The author reads the same Kafka 4.4 topics both as a log and as a queue, using share groups. The argument is that the choice depends on what each consumer needs after reading a message: replay and ordering point to a log, while per-message acknowledgement and work distribution point to a queue. Summarised from the feed preview. [Medium — Santosh Yadav](https://santoshyadav979439.medium.com/kafka-vs-message-queue-when-to-use-which-now-that-kafka-has-queues-5d758c579738)

*Why it matters for us:* With queue semantics now native in Kafka, it is worth asking whether some TIBCO EMS queue workloads could move onto our Kafka platform, which would reduce how many brokers we run. That needs a deliberate ADR, not drift.

**Part 3: Create Identity Protected MCP Tools — John George (tag: azure)** (18 Nov)

The third part of a hands-on series builds MCP tools that validate caller identity tokens, on top of the signing-key refresh added in part 2. It covers how an agent's tool calls get authenticated and authorised, rather than trusting whoever reaches the MCP endpoint. Summarised from the feed preview. [Medium — John George](https://medium.com/@mg8600/part-3-create-identity-protected-mcp-tools-247ec8f02a65)

*Why it matters for us:* Any MCP server we expose over APIM or AKS needs exactly this, with Entra-issued tokens, scopes per tool and key rotation. It pairs with the Entra agent-identity news above.
